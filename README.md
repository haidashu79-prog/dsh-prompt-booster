# dsh-prompt-booster

给"不会写提示词的人"用的提示词自动补全插件。

你说一句不完整的话（"帮我搞个方案"），插件在你按回车之后、模型开始干活之前，
先让一次小模型调用读懂你的真实意图，把这句话补成完整提示词，再交给主线模型执行。
**每一条输入都会自动触发，不需要点按钮，不需要记命令。**

## 为什么默认不改你的原话

插件不改写你输入的消息，而是**在原话后面追加**一条 `[提示词补全]` 消息：

```
[提示词补全] 下面是系统对用户上一条原话的补全稿：意图与原文一致，只是补上了原文省略的背景/目标/约束/交付形式。
执行规则：按补全稿理解需求；补全稿与用户原话冲突时，以用户原话为准。

## 用户原话
帮我搞个方案

## 补全后的提示词
帮我写一份针对昆明中小企业的 GEO 优化方案，面向企业主，600 字左右，给出三步可执行动作。

## 待确认
没说清给谁看

处理方式：不要因为待确认而停下来追问，先按最合理的解释把事做完；做完后用一两句话说明你采用了什么假设，并只在结果会明显不同时补一句追问。
```

这样安排的理由：
- **可审计**：原话永远在，补全稿在旁边，出问题能倒查。
- **不篡改**：补全稿猜错了，原话还在，模型按"以原话为准"的规则回退。
- **不打断**：待确认点不会变成弹窗追问，先干活、事后说明假设。

## 补什么

只补四类缺口，不换任务、不加用户没提的需求：

| 缺口 | 例子 |
| --- | --- |
| 目标 | "搞个方案" → 什么方案、达成什么结果 |
| 输入 | 基于哪份素材、什么对象、什么数据 |
| 约束 | 范围、风格、字数、不要什么 |
| 交付 | 要什么形式、给谁看、什么算达标 |

原话已经说清的部分原样保留，不会为了"显得有用"而注水。原话已经足够清楚时，补全稿基本等于原话。

## 三档强度

| level | 行为 | 长度控制 |
| --- | --- | --- |
| `low` | 只补最必要的缺口，几乎不动措辞 | 原话 1.0~1.5 倍 |
| `high`（默认） | 补齐四类缺口，措辞可整理，不扩写 | 原话 1.3~2.5 倍 |
| `max` | 追加必要的执行细节（步骤/检查点/验收标准），所有推断都标 `(假设: …)` | 原话 2~3.5 倍，≤600 字 |

## 重点标注（v0.4.0 起）

补全稿除了"补全后的提示词"和"待确认"，还会产出一节"重点标注"：把这条任务最关键的 1~4 个要求（目标、对象、硬约束、交付标准）单独拎出来。

- 模型输出里用 `重点:`（也认 `关键点` / `核心要求` / `要点`）小节承载，可以多行。
- 推送给你的补全摘要里，重点会单独成段，每条前面加 `► 重点：` 标记；追加给主模型的 `[提示词补全]` 里也有 `## 重点标注` 一节。
- 默认开启（`showRewrite: true`），你每次发完一句话，会立刻在对话里看到"已补全提示词 + 重点标注"，更直观。

## 用上一轮对话消除指代

"再改改它"这种话离开上下文无法理解。插件会把最近 `contextTurns` 轮的对话（截到 `contextChars` 字）
一起给补全模型，让它知道"它"指的是什么；同时明确要求**不要**把上一轮的旧要求硬塞进这一轮。

## 什么时候跳过

| 原因 | 说明 |
| --- | --- |
| `slash-command` | 以 `/` 开头的命令是 DSH 自己的指令，不补 |
| `too-short` | 短于 `minChars`（默认 4 字），"好""嗯""继续"这类不补 |
| `too-long` | 超过 `maxInputChars`（默认 4000 字），本身已足够详细 |
| `has-attachment` | 带图片/文件的消息不补，避免误解附件 |
| `contains-skip-marker` | 命中 `skipIfContains` 里任一字符串就跳过 |
| `already-seen` | 同一条消息已经补过（同一轮多步不会重复调用模型） |

## 配置

`~/.dsh/profiles/desktop/cordis.patch.yml` 里 `- id: prompt-booster` 一节：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 总开关 |
| `level` | `high` | `low` / `high` / `max` |
| `showRewrite` | `true`（v0.4.0 起） | 把补全稿 + 重点标注也推给用户看一眼（需宿主提供回复服务） |
| `announce` | `false` | 预留 |
| `contextTurns` | `2` | 带几轮历史，`0` 关闭 |
| `contextChars` | `1200` | 历史截断长度 |
| `minChars` | `4` | 少于这个字数不补 |
| `skipIfContains` | `[]` | 命中即跳过 |
| `provider` / `model` | `""` | 留空则跟随当前会话模型 |
| `maxInputChars` | `4000` | 超过不补 |
| `maxOutputTokens` | `900` | 补全稿 token 上限 |
| `timeoutMs` | `20000` | 超时放行原话 |
| `failOpen` | `true` | 补全失败时按原话继续，不阻塞对话 |

改动后重启 DeepSeek Harness 生效。

## 补全时用哪个模型（v0.3.1 起）

补全本身是一次独立的小模型调用，不占用你的对话回合。路由按下面的顺序解析，第一个能拿到的就用：

| 顺序 | 来源 | 说明 |
| --- | --- | --- |
| 1 | 配置里的 `provider` + `model` | 想固定用便宜的小模型补全就填这两个 |
| 2 | `session.requestContext()` | 该会话上一次真实请求解析出的 provider/model（默认走这条） |
| 3 | `session.requestHeader().config` | 同上，从请求头里读 |
| 4 | `agent.options.provider/model` | 兜底 |

> 历史 bug（v0.2.0，已修）：曾用 `agent/request` 事件的 `payload.agent` 做 WeakMap 键记路由。
> 但这是 agent 级 scope 派发的事件，payload 里根本没有 `agent` 字段，键全是 `undefined`，
> 结果每条输入都报 `no route` 并 fail-open 放行原话。另外插件必须在 plugin 里
> `export const inject = ['llm']`，否则取不到 `ctx.llm` 服务（`llm service unavailable`）。

## 校验

- 已通过 canary 自测：首步补全、同一轮多步去重、带历史补全、斜杠命令跳过、短句跳过、模型调用次数符合预期。
- 路由矩阵自测：配置写死 / `requestContext` / `requestHeader` / `agent.options` 四种来源都能补全，全无路由时 fail-open 不崩。
- 全链路自测：pre-step → 路由解析 → `llm.stream` → `BlockAssembler` → `parseRewrite` → 追加注入，注入消息 `source` 正确、原话仍在首位、模型只调一次。
- 真机验证方式：会话日志里出现 `"kind":"plugin","plugin":"dsh-prompt-booster"`。

## 设计取舍（与市场同类对比）

市场上同类插件（如 dsh-prompt-rewriter、dsh-prelude）多为**按钮触发**；少数支持自动触发（如 dsh-prompt-clarifier）。
本插件的差异点：**默认每条输入自动补全、不改写原话、失败自动放行**，
并且把"意图不明"处理成"先按最合理解释做完 + 事后说明假设"，而不是拦下来弹窗追问。
